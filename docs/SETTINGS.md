# Settings

The common ones are in the [README](../README.md#settings). This page lists all of them.

Defaults live in `~/.claude/sitrep/sitrep.conf` or the environment, and the environment wins:

1. `SITREP_QUEUE_ITEMS=<items>` is the queue list limit (default 5).
2. `SITREP_STATUS_LINES=<names>` chooses which lines of the status line's block show: any of `objective`, `progress`, `now` and `queue`, separated by commas (default all four). The order is fixed. The inbox count is part of the queue line. A name it does not know is ignored, and a value with no known name shows all four, so a typo never blanks the status line.
3. `SITREP_HIGHLIGHT_SECONDS=<seconds>` is how long a session counts as recently active, for the dashboard's colour (default 60, and 0 turns it off).
4. `SITREP_HIGHLIGHT_SGR=<codes>` is that colour as terminal SGR codes (default `48;5;238`, a dark grey). Only digits and semicolons are accepted.
5. `SITREP_ATTN_FADE=<seconds>` is how long a session that needs you keeps the needs-you colour in the dashboard, counted from when it began to wait or the dialog opened (default 600; 0 never fades). After that the row is drawn plain, but the `●`, the Needs You count, the sort and the bell are the same, and `needs_input` is still true. Snoozing with `z` is separate.
6. `SITREP_DEBOUNCE=<seconds>` is the time between summaries (default 45; a value that is not a number turns the debounce off).
7. `SITREP_CHECK_UPDATES=<0|1>` lets sitrep look once a day for a newer release (default on; 0, false and no turn it off). See [Updating](INSTALL.md#updating).
8. `SITREP_THEME=<name>` picks the dashboard's colours: `default` (purple, with a pink-red for what needs you), `pastel` (soft lavender, mint and peach), `rainbow` (a colour of the spectrum for each role: a green accent, blue text, orange for recent activity, yellow for what needs you, red for errors), `high-contrast` (stronger colours, for a bright room or a poor screen) or `mono` (no colour at all: bold for recent activity, reverse video for what needs you and for the bars). A name it does not know gives the default.
9. `SITREP_COLORS=<name=colour,...>` changes single colours of the theme: `accent` (the tabs, the rule, the selection bar and the status bar), `dim` (muted text), `hot` (the background of recent activity), `attn` (the background of a session that needs you) and `error` (the block at the left of the status bar while it shows an error: a failed refresh, or a key that was refused or failed) and `snoozed` (the `○` and the state word of a snoozed session, which has no background). A colour is `#rrggbb` or a terminal colour number from 0 to 255, and `light/dark` gives one value for each kind of terminal, as in `SITREP_COLORS='attn=#ffc0c0/#601020,accent=#d9480f'`. The text on the accent colour is chosen to be readable. An entry it cannot read is ignored, and the others still apply. `sitrep colors` is a tool for these two settings: it previews every use of colour and writes `SITREP_THEME` and `SITREP_COLORS` for you (see [the dashboard](DASHBOARD.md#colours)). These win over the theme and over `SITREP_HIGHLIGHT_SGR`, which keeps working for the highlight.
10. `SITREP_TUI_INTERVAL=<seconds or duration>` is how often `sitrep dash` refreshes (default 3 seconds; `5`, `5s`, `1500ms` and `1m` are read, nothing below one second or above a day). `--interval` wins over it.
11. `SITREP_STATE_DIR=<path>` moves the state folder from `~/.claude/sitrep` to a folder of your own, for a demo, a NAS or a test. It is the environment only, since `sitrep.conf` lives inside the folder it would name. It must be an absolute path to a folder of its own: your home folder, Claude's own folder (`~/.claude`, its `sessions` and `projects`) and any folder above them are refused. An existing folder loses its group and other permissions and is never made wider. Only the state moves: `sitrep.conf`, the sessions, the inbox and the update record go there, and the program stays in `~/.claude/sitrep/bin`, where the hooks run it. Set it in the shell that starts `claude`, since the hooks, the status line and the summarizer take it from there, and set it for your own `sitrep` commands too, or they will read the default folder. A value that is not an absolute path is refused, never read as relative: the hooks then do nothing and succeed, the status line says what is wrong, and every other command fails and changes nothing. `sitrep setup` and `sitrep migrate` refuse while it is set, so unset it for those.
12. `SITREP_LOG=<on|off>` turns on the history log (default off), and `SITREP_LOG_MAX=<megabytes>` (default 10) and `SITREP_LOG_DAYS=<days>` (default 30) limit it, whichever is reached first. See [the history log](LOG.md).
13. `SITREP_QUEUE_NUDGE=<on|off>` makes the hooks tell Claude, at a session start and when the count changes, how many items the session's queue holds, so that it asks you whether to start the next one when a task is done (default off). The line holds the count and the session id and never an item's text, and Claude never starts an item without your yes. The `sitrep-queue` skill tells Claude what to do with the line. See [QUEUE-NEXT.md](QUEUE-NEXT.md).

`sitrep.conf` holds `NAME=value` lines, with single quotes, double quotes and backslashes understood. It is read and never run, so it can hold no commands, and setup replaces or removes only its own `SITREP_HUD_CMD` line and its block of examples. A line that starts with `#` is a comment and is ignored. Setup keeps a block at the end of the file that lists every setting above, commented out with its default, between `# >>> sitrep settings` and `# <<< sitrep settings <<<`. Uncomment a line there or, better, put your own line above the block, since setup replaces the block as a whole each time it runs (and `/sitrep:setup remove` takes it out).
